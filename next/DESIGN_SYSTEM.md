# QWIZ-PARTY — UI / UX Design Contract (v5)

Основание: пользовательский референс EduWay (светлая плотная панель, пастельные акценты), исходные правила `ui-ux-pro-max` (официальный GitHub: nextlevelbuilder/ui-ux-pro-max-skill, категории accessibility, touch, performance, typography, form feedback, responsive). Исходник пользовательского референса — изображение, не копия экрана EduWay.

## Тип продукта и основное действие

Сценарий: учебная командная интеллектуальная игра. Самое важное действие — участник вводит 8-символьный код и присоединяется. Преподаватель переключает роль и входит в кабинет. QR-код виден сразу справа на десктопе и под формой на телефоне.

Не создавать рекламные экраны, «фальшивые» панели участников, декоративные графики без данных, лишние заголовки и повторные меню.

## Компоненты

- `welcome-head`: единый информативный заголовок + ровно одно подзаголовочное предложение
- `entry`: строго одно активное содержимое роли, две вкладки, проверяемые поля с явными подписями, один основной CTA
- `qr-card`: QR генерируется локально, диалог увеличения, копирование ссылки
- `welcome-footer`: три коротких проверяемых свойства платформы, без рекламы
- `sidebar`, `panel`, `game-card`: общие токены для кабинета и игры, не дублировать стиль
- `presenter`: отдельный CSS в `presenter.css`; вопросы без ответов/пульта

## Строгие правила изменений

1. **Не добавлять новый CSS-файл поверх старых.** `next/app.css` — единственный источник стилей приложения; `presenter.css` принадлежит только проектору.
2. Не добавлять снова `home-rail`, большие «hero», кольца, скриншоты-фейки, бесполезные панели.
3. Любое поле имеет видимый `label`, сообщение ошибки, клавиатурный `:focus-visible`, область нажатия 44 px и больше.
4. QR обновлять только при изменении URL комнаты, не при каждом получении очков/состояния.
5. Минимизировать сторонние ресурсы и сохранять кэширование файлов по версии.
6. Перед публикацией `node --test next/test.mjs` и Playwright на 320/360/390/768/1440 px: QR, ввод кода, роли, отсутствие горизонтального скролла, кабинет, экран игрока и проектор.
7. Не менять auth, игровые RPC и Supabase из-за задач внешнего вида. Не ломать старую игру `/ORG/`.
8. При изменении дизайна сверять реальный скриншот, а не только синтаксис и счётчик тестов.
