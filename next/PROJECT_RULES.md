# QWIZ-PARTY — обязательные правила игрового движка

Обновлено: 2026-10-25. Эти ограничения относятся к любым текущим и новым вопросам/раундам/играм; их нельзя менять при редизайне без согласования.

## 1. Позиции вариантов ответов (обязательно)

- Нельзя использовать фиксированный индекс правильного ответа, включая 4/D или 1/A.
- Случайный порядок создаётся на сервере один раз при подготовке снимка комнаты.
- Каждая перестановка обязана переносить **вместе** варианты, индексы правильных ответов `solution.correct`, `solution.correct_indices` и связанные подписи `solution.option_labels`.
- База вопросов хранит исходные ключи; изменение порядка в игре не меняет исходное содержимое банка.
- Во время вопроса корректные индексы не раскрываются клиенту; по завершении они показываются в новом, фактически предъявленном порядке.
- После F5, переподключения, повторного polling и перехода фазы порядок уже показанных ответов **никогда не меняется**.
- Блиц-вопрос подчиняется тем же правилам: исходные индексы переводятся обратно сервером через сохранённый `option_order`.
- Новые типы ответов обязаны иметь тест инвариантности и переноса правильного ключа; нельзя рандомизировать `order`, `match` и другие семантически упорядоченные массивы по схеме одного варианта.

## 2. Карта регионов

- В режиме «Найдите субъект» до проверки названия областей/краёв/республик не появляются ни на карте, ни в тексте кнопки, ни в подписи при наведении.
- Первое нажатие только выбирает геометрию и открывает «Подтвердить выбор»; самостоятельного начисления до подтверждения нет.
- После проверки верный регион всегда зелёный; неверно выбранный — красный, фокус карты переводится к правильному региону; при необходимости показывается название.
- Масштабирование, перемещение, клавиатурный выбор, доступность и клики на соседних полигонах тестируются отдельно.

## 3. Обязательные игровые механики

Режимы сохраняют старые внутренние ключи для совместимости старых сборок, но правила новые:

| Ключ | Название | Кто управляет | Победа |
| --- | --- | --- | --- |
| `rocket` | Забег с препятствиями | Один случайно выбранный сервером игрок из каждой команды | Больше препятствий, пройденных без столкновения |
| `tug` | Командная тапалка | Каждый игрок команды | Сумма реально подтверждённых нажатий всех игроков команды |
| `captain` | Дуэль капитанов · Memory | Самый ранний вошедший игрок каждой команды — капитан по существующему правилу | Сначала полностью пройденные пары, затем меньшее время; при равенстве — меньше ходов |
| `blitz` | Блиц-вопрос | Победившая в захвате команда | Сохраняет прежние правила и награды |

- В раннере сервер создаёт участника команды ровно один раз для карточки; прыжок валидируется по серверному времени относительно препятствия.
- В Memory сервер хранит закрытый набор и отдаёт игроку только открытые/совпавшие плитки. Все капитаны стартуют параллельно.
- Результаты команд, бонусы и раунды определяются сервером. Участники и общий экран не могут завершать карточку по локальному таймеру.
- Не менять награды +25/+15 без согласования. Старые улучшения «ракета» и «хват» недоступны для новых режимов.

## 4. Стандартизация экранов

- Все результаты и итоговые таблицы: min-width:0 для flex/grid-детей, перенос длинных ФИО, `font-variant-numeric:tabular-nums`, адаптивный размер чисел, отсутствие горизонтального скролла на 320/390/768/1280/1920 px.
- Количества склоняются через `Intl.PluralRules('ru')`: «1 вопрос», «2 вопроса», «5 вопросов»; «1 участник», «2 участника», «5 участников».
- Для бонусов/штрафов игрок видит два шага голосования: стратегия (себе/сопернику), конкретный эффект, правила большинства и оставшееся серверное время.

## 5. Гейт релиза

До публикации необходимы зелёные тесты JS/SQL, проверка CSS на телефоне и внешнем экране, и минимум одна полноценная сессия с двумя командами и капитанами. Нельзя выкладывать только фронтенд, пока миграции Memory/раннера не применены и не проверены. Прямые DDL в работающую production-БД без проверки запрещены.
