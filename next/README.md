# ORG/PARTY 2 — новая версия

## Что это
Пересобранный с нуля отдельный интерфейс (`next/index.html`, `next/app.css`, `next/app.js`) и новый компактный игровой движок PostgreSQL (`next/migration.sql`). Старый `index.html`, `app.js` и все `org_quiz_*` не затронуты.

## Пользовательские маршруты
- Участник: код комнаты (8 символов) → имя / группа → команда → вопрос → один ответ → открытие правильного ответа → результат.
- Преподаватель: вход Supabase → Библиотека → Провести игру → Результаты. В библиотеке возможно создать тест, импортировать прежние вопросы типа `single`; в комнате — создать, распределить игроков и управлять раундами.
- Состояния комнаты: `lobby` → `question` → `result` → `question` … → `finished`.

## Модель данных
5 таблиц: `org_next_quizzes`, `org_next_rooms`, `org_next_teams`, `org_next_players`, `org_next_answers`.
- Ответы и ключи вопросов не доступны клиенту напрямую.
- RLS включён, прямые права на таблицы отозваны у `anon` и `authenticated`.
- RPC c проверкой `auth.uid()`; админские методы требуют `org_quiz_is_admin_check()` и принадлежности комнаты.
- `org_next_state()` не раскрывает `correct` и `explanation` участникам, пока идёт вопрос.
- Атомарная запись ответа через уникальность (комната, игрок, вопрос), очки начисляются сервером.

## Защита и ресурсная нагрузка
- Браузер получает только Supabase publishable key, никогда service-role ключ.
- Приём ответов прекращается по серверному времени.
- Realtime используется как сигнал «обновить состояние» без пересылки ответов; периодическое обновление раз в 30 секунд — резерв на случай потери сигнала. Фоновая вкладка не опрашивает комнату.
- Предельное количество игроков одной комнаты — 80 (это лимит, **не** результат нагрузочного теста).

## Ограничения текущей версии
- Реализованы только тестовые вопросы с одним вариантом ответа. Новые дуэли, раунды выбывания, спасения, перехваты, банк силы, карта и мультимедиа ещё не перенесены в новый движок. Они остаются в прежней версии.
- Миграция создаёт отдельные объекты **в уже общем Supabase-проекте**, а не отдельный физический Supabase-проект.
- Не проводились сквозные тесты со студентами и преподавателем и нагрузочное испытание на 40+ одновременных соединений; CI проверяет синтаксис, интерфейсные контракты и ограничения прямых обращений к базе.
- Размещение `/next/` не меняет старый URL приложения. Переключение главной версии допустимо только после сравнения функциональности и проверки реальных сценариев.

## Запуск
`python -m http.server 8080` из корня репозитория, затем `http://localhost:8080/next/`.

## Проверки
`node --test next/test.mjs`

## Архитектурные решения
- Не добавлять новый CSS-слой поверх старого. Для `next/` есть ровно один стиль и один клиентский модуль.
- Не переносить старые таблицы копированием без проверки ACL.
- Не менять ГОС.ID: префикс `org_next_` специально изолирован.
- Любые будущие механики оформлять в явные серверные переходы с проверками полномочий и идемпотентностью.
