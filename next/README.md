# QWIZ-PARTY 3 — новая версия

## Что это
Пересобранный с нуля отдельный интерфейс (`next/index.html`, `next/app.css`, `next/app.js`) и новый компактный игровой движок PostgreSQL (`next/migration.sql`). Старый `index.html`, `app.js` и все `org_quiz_*` не затронуты.

## Пользовательские маршруты
- Участник: код комнаты (8 символов) → имя / группа → команда → вопрос → один ответ → открытие правильного ответа → результат.
- Преподаватель: вход Supabase → Библиотека → Провести игру → Результаты. В библиотеке возможно создать тест, импортировать прежние вопросы типа `single`; в комнате — создать, распределить игроков и управлять раундами.
- Состояния комнаты: `lobby` → `question` → `result` → `question` … → `finished`.

## Модель данных
5 таблиц: `org_next_quizzes`, `org_next_rooms`, `org_next_teams`, `org_next_players`, `org_next_answers`.
- Ответы и ключи вопросов не доступны клиенту напрямую.
- RLS включён, прямые права на таблицы отозваны у `anon` и `authenticated`.
- RPC c проверкой `auth.uid()`; админские методы требуют `org_quiz_is_admin_check()` и принадлежности комнаты.
- `org_next_state()` не раскрывает `correct` и `explanation` участникам, пока идёт вопрос.
- Атомарная запись ответа через уникальность (комната, игрок, вопрос), очки начисляются сервером.

## Защита и ресурсная нагрузка
- Браузер получает только Supabase publishable key, никогда service-role ключ.
- Приём ответов прекращается по серверному времени.
- Realtime используется как сигнал «обновить состояние» без пересылки ответов; периодическое обновление раз в 30 секунд — резерв на случай потери сигнала. Фоновая вкладка не опрашивает комнату.
- Предельное количество игроков одной комнаты — 80 (это лимит, **не** результат нагрузочного теста).

## Ограничения текущей версии
- Реализованы только тестовые вопросы с одним вариантом ответа. Новые дуэли, раунды выбывания, спасения, перехваты, банк силы, карта и мультимедиа ещё не перенесены в новый движок. Они остаются в прежней версии.
- Миграция создаёт отдельные объекты **в уже общем Supabase-проекте**, а не отдельный физический Supabase-проект.
- Не проводились сквозные тесты со студентами и преподавателем и нагрузочное испытание на 40+ одновременных соединений; CI проверяет синтаксис, интерфейсные контракты и ограничения прямых обращений к базе.
- Размещение `/next/` не меняет старый URL приложения. Переключение главной версии допустимо только после сравнения функциональности и проверки реальных сценариев.

## Запуск
`python -m http.server 8080` из корня репозитория, затем `http://localhost:8080/next/`.

## Проверки
`node --test next/test.mjs`

## Архитектурные решения
- Не добавлять новый CSS-слой поверх старого. Для `next/` есть ровно один стиль и один клиентский модуль.
- Не переносить старые таблицы копированием без проверки ACL.
- Не менять ГОС.ID: префикс `org_next_` специально изолирован.
- Любые будущие механики оформлять в явные серверные переходы с проверками полномочий и идемпотентностью.

## QR-код и режим второго экрана (2026-10-22)
- На главной размещён QR-код страницы входа, который можно увеличить нажатием. Если у преподавателя открыта игровая комната, QR ведёт напрямую в неё.
- В кабинете рядом с настройками комнаты тоже есть QR-код для присоединения к конкретной игре. QR генерируется локально в браузере из ссылки: третьим сторонам адрес комнаты не отправляется.
- Кнопка **«На второй экран»** открывает `/next/presenter.html?room=...` в отдельном окне. На основном мониторе остаётся пульт с правильными ответами и управлением; на проекторе выводятся только вопрос, варианты и таймер.
- При поддержке Window Management API и разрешении браузера система попытается поставить окно на второй дисплей. Иначе преподаватель переносит окно с помощью **Win + Shift + ←/→** и включает полный экран кнопкой или F11.
- Отдельный RPC `org_next_presenter_state()` разрешён только владельцу/участнику комнаты и возвращает ограниченное состояние без правильного ответа. Синхронизация через Realtime и BroadcastChannel; резервное обновление раз в 12 секунд.
- Максимальное число команд — **15**, ограничение исправлено и в PostgreSQL CHECK, и в RPC создания комнаты, и в выпадающем списке.
- Визуальный ориентир: предоставленный пользователем скриншот EduWay. Сохраняется оригинальная структура квиз-приложения с отдельными панелями, QR и проекцией; это не копия дизайна.
- Основная старая игра остается доступна на `/ORG/`; новый интерфейс — на `/ORG/next/`. Данные `org_quiz_*` и ГОС.ID не мигрировались и не удалялись.


## QWIZ-PARTY Studio v4 — 2026-10-22

Основные адреса:
- \`/ORG/next/\` — вход участника или преподавателя, открытие экрана аудитории
- \`/ORG/next/workspace.html\` — студия преподавателя, авторизация той же учётной записью на компьютере/планшете/телефоне
- \`/ORG/next/presenter.html\` — публичный экран аудитории без входа преподавателя, выбор комнаты по 8-символьному коду
- \`/ORG/next/profile.html\` — студенческий профиль, пароль и личный одноразовый QR для другого устройства

### Банк
Банк поддерживает 22 категории хранения вопросов: один/несколько вариантов, да-нет, соответствие, порядок, текст, числа, изображения, аудио, видео, флаги, лица, карту, даты, последовательности, загадки, аукцион, блиц, опрос и др. Полная **серверная игровая проверка** пока реализована только для одного варианта, да/нет и тестов с изображением/флагом/портретом с одним правильным вариантом. Другие форматы можно сохранить, но они НЕ запускаются в сборке, пока не появится соответствующий оценочный движок.

### Сборки
Сохраняемые игры \`qwiz_builds\`, карточки \`qwiz_build_cards\` с позицией, темой, лимитом команд и участников (NULL — без ограничений), количеством/порядком/смещением вопросов, временем и звуковым пресетом. Перетаскивание карточек мышью; стрелки для клавиатуры/телефона. Финальная карточка обязательна. При запуске создаётся неизменяемый снимок тестовых вопросов в новой \`org_next_quizzes\` и связывается с новой комнатой.

### Реальный ход игры
Сервер управляет состояниями: lobby → intermission (вступление/перерыв/статистика) → countdown (5 секунд) → question → result → ... → finished. До завершения countdown клиентам не выдаётся вопрос или правильный ответ. Финал выводит сначала командную, затем обезличенную индивидуальную статистику на экран аудитории. Звуки на проекторе включаются только после пользовательского нажатия из-за политики autoplay браузеров; используются синтезированные короткие эффекты без внешних аудиофайлов.

### Многопользовательская синхронизация
Комната и фаза хранятся в PostgreSQL, а не в конкретной вкладке. Любой вход преподавателя получает перечень его комнат через \`qwiz_host_rooms()\`. Сервер транслирует события фазы через Supabase Realtime Broadcast (без ключей, ответов и персональных данных), есть резервный опрос. Компьютер в аудитории использует только \`qwiz_public_screen()\`. Список команд и участников доступен преподавателю по защищённой RPC.

### Студенты
Универсальный профиль \`qwiz_student_accounts\`; соль+bcrypt, логин и пароль. На каждом устройстве действует отдельная анонимная Supabase-сессия, привязанная к одной студенческой записи. Повторный вход в одну комнату с нескольких привязанных устройств обращается к одному игроку; уникальный ответ на вопрос предотвращает повторное начисление. Самостоятельно изменяются ФИО, ник, пароль, SVG-аватар; личная статистика агрегируется по аккаунту. Одноразовый QR-перенос устройства живёт пять минут, токен хранится в базе только как SHA-256. Общий QR аудитории НЕ является ключом к профилю.

### Ограничения
- База и основные интерфейсы изменены; **сквозной тест реальными аккаунтами преподавателя и 40 студентов не выполнен**. Автоматические браузерные тесты используют изолированные mock-ответы.
- Лимит комнаты по прежнему остаётся 80 человек (технический предел), но нагрузка на 40+ одновременных клиентов не подтверждена.
- Музыкальные заставки — синтезированные эффекты, не полноценные тематические аудиотреки или мемы.
- Пользовательские изображения доступны по внешним HTTPS URL; собственной безопасной загрузки медиа ещё нет.
- Для расширенных форматов сохранения есть шаблоны; их серверная оценка не завершена.
- Старый вход \`/ORG/\` не изменён. Не пересоздавать существующие legacy таблицы и базы ГОС.ID.
